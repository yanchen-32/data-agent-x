## 2. 总体说明与系统边界

### 2.1 产品定位

DataAgentX 是面向模拟电商经营数据异常调查的可验证 AI Agent 系统。首版比较两个成熟历史支付窗口，支持总体或一个授权地区内按品类/渠道/地区单维分组；先过滤再聚合，不能用全局品类与地区两张边际汇总推算地区内部品类贡献。

系统输出经核对的事实、算术贡献与待验证假设。首版不提供因果识别能力；业务干预由人审阅执行。RAG 支撑指标和规则查询；长期记忆作为后续实验能力。

## 3. 业务运行概念

### 3.1 使用场景

| 场景 | 输入及前提 | 正常结果 | 关键异常处理 |
| --- | --- | --- | --- |
| UC01 成熟历史退款率异常调查 | 授权域；两成熟历史支付窗；固定H/as_of/水位 | 质量检查、算术贡献、证据报告 | 最近一周未成熟支付队列不在R0；须澄清或证据不足 |
| UC02 口径或范围澄清 | 缺指标、基期、时间或存在定义冲突 | 显示候选解释；补充后继续原任务 | 未授权默认值不得静默采用 |
| UC03 混杂或假异常 | 可按品类、渠道、地区分层；含质量异常案例 | 区分结构变化、组内变化和数据问题 | 不能将相关关系或重复数据认定为真实因果 |
| UC04 历史案例复用 | 已审核且当前有权限的案例；Should | 将历史线索转换为待核验路径 | 过期、冲突、污染案例不得作为当前证明 |
| UC05 故障、取消或预算到界 | 可注入模型、数据库、检索故障 | 有限恢复或明确终止；保留授权证据 | 不无限重试、不在终态后继续发起调用 |
| UC06 演示与复现 | 冻结版本、数据、配置和运行说明 | 新环境启动；Mock/真实演示；复查报告和评测 | Mock 结果不得冒充真实模型效果 |

### 3.2 任务状态契约

| 状态 | 进入条件 | 允许后继 |
| --- | --- | --- |
| 待校验 `validating` | 身份已核验并创建合法任务，业务范围尚待确认 | 待澄清、运行中、失败、已取消 |
| 待澄清 `needs_clarification` | 缺少决定口径/范围的条件 | 运行中、失败、已取消 |
| 运行中 `running` | 身份、口径、范围和预算可用 | 待澄清、已完成、证据不足、失败、已取消、预算终止 |
| 已完成 `completed` | 完成必要调查及核验，报告含所需证据 | 终态，无后继 |
| 证据不足 `insufficient_evidence` | 数据不可比、关键证据缺失或结论冲突不能消除 | 终态，无后继 |
| 失败 `failed` | 权限拒绝、不可恢复技术故障或校验超时 | 终态，无后继 |
| 已取消 `cancelled` | 用户显式取消；仅选中SC-01时才启用其控制断连终止 | 终态，无后继 |
| 预算终止 `budget_exceeded` | 总时长、工具数、模型数或 Token 预算触限且仍需继续调用 | 终态，无后继 |

无异常且证据充分的任务可以 `completed`。预算恰好耗尽但已具备全部输出条件时可以完成；不能再追加调用。错误状态必须另带稳定的 `reason_code`，例如 `AUTH_DENIED`、`DB_TIMEOUT`、`DATA_NOT_COMPARABLE`。

状态提交必须原子化，取消、完成和预算到界竞争时只提交一个终态，以首先成功提交的事件为准，保存其他事件时间。终态后不得产生新工具/模型请求，迟到结果仅可记入受控审计，不能覆写终态报告。取消接口幂等，取消已终结任务时返回现有终态。

计时分为累计Queue Waiting（就绪队列，默认≤30秒）、累计Active Execution（持执行槽的调查、调用等待与退避，≤120秒）和End-to-End（受理至终态完整墙钟）。人工澄清释放槽并暂停前两者，累计等待≤1800秒。重新入队不重置任何计数；队满受理前429且不创建任务，已受理任务队列超时failed/QUEUE_WAIT_TIMEOUT，执行耗尽budget_exceeded/ACTIVE_DEADLINE_EXCEEDED，澄清到期failed/CLARIFICATION_EXPIRED。到界关闭新发并有界收尾，端到端另含收尾，不把外部远端结束时间冒充本地可保证期限。

普通POST返回和SSE观察断开均不取消。R0采用显式REST取消；WebSocket控制租约/epoch/心跳及5秒断连恢复移至SC-01条件Should子能力，默认关闭，不阻塞R0。未来选择SC-01须另登记配置版本及取消/权限/恢复回归。30分钟人工澄清超时与原取消2/5/10秒仍为核心。

## 4. 数据与业务语义要求

### 4.1 数据对象与粒度

| 对象 | 最低数据语义 | 必须保持的约束 |
| --- | --- | --- |
| orders | 一个订单一行；order_id、paid_at、支付有效性、region_id、channel_id、product_id及访问域 | 主键唯一；符合条件订单的排除规则版本化；多品订单须预先约定订单归类规则 |
| refunds | 一个退款事件一行；refund_id、order_id、refund_at、status及访问域 | 同订单可多事件；仅成功退款使订单进入分子；重复事件不得重复计数 |
| products/regions/channels | 维度键、标签及适用版本/有效区间 | 首版使用固定快照；联接不扩大订单粒度；缺失维度按已声明规则阻断或归入未知组 |
| 指标定义 | metric_id、version、分子/分母、去重键、过滤、时间、单位、维度、有效区间、来源 | 任务固定所使用版本；定义冲突须澄清；不能混用两个版本 |
| 知识片段 | document_id、version、chunk_id/位置、来源、有效区间、访问域、内容 | 生成前完成权限与适用时间过滤；内容中指令不获得权限 |
| 证据与报告 | evidence_id、task_id、来源对象、查询/分析版本、范围、快照、结果及校验状态 | 关键断言可追溯到证据；证据不存在或不支持断言时不能判通过 |
| 案例记忆（Should） | 审核状态、source、entity、created_at、valid_from/to、版本与访问域 | 与当前业务事实分离；旧案例只能提供线索 |

首版仅使用合成数据或明确获准的公开数据；不保存真实客户个人信息。原始数据、知识片段、工具结果、任务、证据、轨迹和报告均继承访问域。禁止只在最终报告阶段过滤越权内容。

### 4.1.1 单地区过滤与Scope不变量

`filters={"region_ids":[]}`代表当前授权域全部地区；`["region_northwest"]`代表恰好一个已注册且当前主体可访问的地区。字段省略只在服务端登记默认为全部时规范为[]并披露，不能把用户明确地区意图忽略成全部。空对象、两个ID、名称直接作ID、未知/跨域ID均拒绝或澄清，未授权403。名称由当前域目录映射，名称重复必须澄清。

先限定授权域/快照/地区与支付窗，再以EXISTS去重退款，再按一个dimension聚合。总计与每份分解均继承同一过滤、窗口、H和版本，并在证据中绑定scope_hash。冻结后模型不得覆写过滤；需要另一个地区时创建显式新任务/新Scope，原证据不能移用。未知地区组ID为__unknown__，不是SQL标识符。

贡献断言使用dimension_id＋group_id＋contribution_type（within/structure/entry/exit）＋formula_version，名称只显示。同名品类/地区不同键，组内/结构不同分量；Verifier按完整键定位分析证据并复算，拒绝串组/串分量/错公式。

### 4.2 退款率定义与时间边界

首版指标为订单队列退款率。比较窗采用半开[start,end)。外部接收显式Z或±HH:MM偏移RFC3339、0–6位小数；拒绝无偏移、-00:00未知偏移和闰秒。进入系统规范为UTC微秒Z；business_timezone只决定显示与已明确的日历边界解释，不覆盖输入偏移。语义冲突先澄清，规范化后计算scope与幂等hash。

对窗口 W，`O(W)` 是支付时间落在 W 内且满足该指标版本有效性规则的去重订单集合。`A` 是观察截止时刻，`H` 是统一退款观察时长。为避免不同成熟期形成假变化，可比较的冻结口径为：

```text
denominator(W) = |O(W)|
numerator(W,H,A) = 满足以下条件的 O(W) 中订单数：
  至少一笔成功退款的 refund_at 位于 [paid_at, paid_at + H]，且 refund_at <= A
refund_rate(W,H,A) = numerator / denominator
比较前提：两个队列中每个纳入订单均满足 paid_at + H <= A，且数据水位覆盖所需观察期
```

`H` 必须来自冻结指标目录或明确确认的请求，不能由模型猜测；本规格不假造适用于所有业务的天数。固定 H 及对晚于 H 的退款进行排除，是对上一阶段“成熟期一致”的工程细化，不表示已取得真实业务口径认可。若要采用“截至 A 的累计退款率”，须另建指标版本，不能沿用此比较结果。

当“最近一周”包含尚未成熟订单时，应解释不能直接比较并请求选择成熟窗口或其他已定义指标，不能静默删除近期订单、移动窗口或更改H以得到结论。

同一订单多笔或部分成功退款均只计一次；只有失败/处理中退款不计入分子。支付前退款、孤立退款及重复订单属于质量异常。分母为零时结果为未定义，不记为0%；一窗无有效样本时返回证据不足。时间水位和数据库快照必须记录，不能把缺少近期退款记录直接解释为0。

变化必须同时区分：`绝对差 = 当前率 - 基期率`，以百分点展示；`相对变化 = 绝对差 / 基期率`，仅当基期率非零时计算。基期为零时相对变化标为未定义，禁止输出无穷增长或静默除零。

### 4.3 分层贡献规则

每次分解使用互斥且穷尽的分组；地区、品类和渠道的三次独立分解不得直接相加。维度联接保持订单粒度，多品归类规则须在查询前明确。

对两窗均有订单的分组 i，基期权重/退款率为 `w_bi/r_bi`，当前值为 `w_ci/r_ci`。本轮采用对称分解作为首版可复算要求：

```text
组内变化贡献_i = (w_ci + w_bi) / 2 * (r_ci - r_bi)
结构变化贡献_i = (r_ci + r_bi) / 2 * (w_ci - w_bi)
两项之和 = w_ci*r_ci - w_bi*r_bi
```

只在当前窗出现的组单列“新增组贡献” `w_ci*r_ci`；只在基期出现的组单列“退出组贡献” `-w_bi*r_bi`，不为无订单组编造退款率。共享组的两类贡献加上新增/退出贡献，必须在 N02 容差内等于总体率差。分解方法及版本进入证据。

展示正、负贡献及未解释残差；净变化接近零时不得以“贡献占净变化百分比”制造极端结果，默认报告百分点。样本量和未知分组必须披露。该分解是算术解释，不构成因果证据。

示例：两品类退款率固定为10%、40%，权重由80%/20%变为60%/40%，总体由16%变为22%。应报告上涨6个百分点，相对上涨37.5%；全部6个百分点来自结构变化，不能声称两个品类自身退款率恶化。

### 4.4 数据质量处置与一致性

| 情况 | 最低处置 |
| --- | --- |
| 分母为零、关键时间缺失、无法统一成熟期、关键数据水位不足 | 阻断受影响比较，返回证据不足及恢复条件 |
| 去重失败、联接膨胀、重复支付订单、跨域混入 | 修复并重新校验，或阻断；不得仅附警告后继续给出原总体结论 |
| 可定位的非关键维度缺失 | 依冻结规则归入未知组并披露规模；未经证实不删除样本 |
| 查询截断或结果不完整 | 返回 `truncated=true`；完整聚合改在数据库端计算；截断样本不能证明总体 |
| 任务中源数据改变 | 使用固定快照/数据版本；无法维持一致时中止受影响结论并披露差异 |

质量阈值、修复规则、快照及水位属于运行配置与证据，不能由模型临时变更。首版合成数据的固定快照优先，不强制建设生产 ETL 系统。

### 7.2 预算、取消与性能解释

1. 每次实际向下游发出的工具调用计1次，重试/失败也计入；模型请求独立计数。执行前参数拒绝不计下游调用，但计入受控状态步骤，不能形成无穷模型纠错循环。
2. 本地准入以完整上下文估算输入和请求最大输出预留，默认累计20000/4000；调用次数≤8。所有预留原子化、失败/重试共享；已发unknown保守占额、证明未发才释放。audited模式保证本地账本/发送准入，不等同供应商实际计费Token保证。
3. audited默认允许真实小样本接入并记录计数误差、隐藏Token/在途/usage未知；实际超额或无法继续保证本地准入时停新发并审计，不记0。strict_calibrated须可验证整请求计数上界才宣称严格通过；Mock不能替代真实校准。价格未知标未能估算，不运行无界付费批次。
4. 本版不虚构人民币/美元硬金额上限；费用按带日期价格配置与实际usage计算。调用次数/本地预留是可强制资源控制，第三方实际Token/账单是单独审计，不混作同一种保证。
5. 取消后本地编排5秒收尾不包含已受理外部模型请求和数据库端收尾；数据库单独受10秒限制。供应商无法撤销的请求单列“在途残余”，不得计为取消后的新发起请求。
6. 调查执行时间和接收接口延迟分别统计；接收接口必须返回task_id或明确拒绝。Mock测试工作量、后台并发、排队上限及缓存状态预先冻结，不能只测空接口或以长队列掩盖过载。
7. 默认阈值继承SRC-01或明确标注的本轮细化。可行性校准须在正式验收前完成，并记录旧值、新值、理由及影响；不得看见盲测结果后降低门槛。

## 8. 报告与证据契约

报告至少包含：原请求及澄清、授权范围、指标/公式版本、两比较窗、观察截止时刻/H/时区、数据快照/水位、质量问题及处置、异常幅度、样本量、结构/组内贡献、结论等级、逐项证据、限制、下一步验证、最终状态及原因、实际耗时与预算使用。

每个关键事实或贡献断言必须关联可解析的 evidence_id；证据同时关联query_id/analysis_id或document_id/version/位置。核验记录必须说明“存在”“数值相符”“语义支持”三个不同检查结果。纯建议和价值判断单独标记，不混入可验证事实分母。

`Confirmed` 不允许用于未经因果识别的“活动导致退款增长”。对候选原因可写“与X变化相关”“在当前分解中贡献Y个百分点”“需补充实验或对照验证”。证据不足报告必须说明缺什么、影响哪些结论以及怎样恢复调查；不能以空报告通过证据精度门槛。

## 9. 验证与验收

### 9.1 测试数据、隔离与对照

合成业务数据包含orders、refunds、products、regions、channels和规则文件，保存生成器版本、种子、哈希及冻结快照。调查case至少120个：开发30、验证30、盲测60；按事件及生成机制分组隔离，同事件变体不得跨集合。

盲测六类各10例：单因素、混合因素、结构变化、数据质量假异常、口径/条件歧义、无异常/证据不足。每例预先标注允许数据、正确口径、必要数值/因素、必要证据、允许终态、禁止断言及澄清脚本。澄清脚本仅提供正常使用者可知条件，不包含真值答案；补充时间不计120秒执行预算。

基线B0为有相同目录/DQ/查询/分析/知识/核验/报告能力及预写分支的确定性工作流；B1单次工具决策（可一次最终报告生成）、B2反馈式多步Agent无Memory；B3为Memory增强。数据、权限、工具、知识、预算、计时和评分一致；规则基线不读答案。simple/dynamic及机制标签预先冻结，质量/成本配对比较不预设Agent获胜。每case/config至少3轮，B0无模型如实记0。

盲测标签仅评分可见，不进入模型、知识或记忆。公开演示和bad case回归使用开发/已退役用例；盲测被查看后调参必须换用新的冻结盲测，不将旧集继续宣传为未见测试。

### 9.4 增强实验及默认启用条件

Memory须预先冻结历史相关子集和主指标；默认启用要求该子集成功率相对No Memory提高至少5个百分点、总体不下降超过2个百分点，并且时效/污染/权限硬例零违规。同步报告成本、延迟及配对区间；此项目门槛不是统计显著性的自动证明。未达到时可以验收“实验已完成”，但必须标“默认启用条件未满足”。

检索增强的主指标和可接受退化在实验前定义并冻结；不得事后挑选有利指标。Go不设“必须更快”，以延迟、取消、资源治理及复杂度决定保留，允许真实无收益结论。
