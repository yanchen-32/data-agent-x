- [参数化回归记录](../regression_checks/A3-04_A3-05_parametrized.md) 进一步保存 A3-04 测试侧独立输入规则核验，以及 A3-05 西北集合、精确率和变化。该记录区分诊断和参考函数实际返回的发布字段；本轮复用其已有数值，不重跑计算。
- [2026-10-14 人工记录](2026-10-14.md) 只覆盖成熟/水位及 UTC 两例，不将它冒充 A3-04/05 的独立人工记录。

本例固定 `region_ids=[region_northwest]`，原始订单6行、退款3行。西北已注册且获授权是合成场景前提，不代表本轮实际验证了鉴权。

| --- | --- | --- | --- |
| `f-row-nb1` | `F-N-B1` | 西北，09-02有效支付，基期 | 纳入；`FR-N-B1`于09-04成功退款，在该单观察期内 |
| `f-row-nb2` | `F-N-B2` | 西北，09-03有效支付，基期 | 纳入；无退款 |
| `f-row-nc1` | `F-N-C1` | 西北，09-09有效支付，当前 | 纳入；`FR-N-C1`于09-12成功退款，在该单观察期内 |
| `f-row-sb1` | `F-S-B1` | 东南，基期 | 地区不符，订单及其成功退款`FR-S-B1`均排除 |

退款行不含地区字段，必须按 `(domain_id,snapshot_id,order_id)` 关联已经筛选的支付订单；不能只过滤分母或只过滤分子。分子集合必须是该窗分母订单集合的子集。

输入支持既有集合：基期支付 `{F-N-B1,F-N-B2}`、退款 `{F-N-B1}`；当前支付和退款均为 `{F-N-C1}`。复用并核对既有结果：基期 N=2/U=1/率=1/2，当前 N=1/U=1/率=1；绝对变化 `1−1/2=1/2`，即上涨50个百分点，相对变化为1，即100%。

西北纳入订单最晚于09-16成熟，as_of/退款水位09-23及支付水位09-15完整覆盖，无重复业务键。与冻结预期一致：`outcome=ready`，无不足原因，样例中的发布指标与上述有效结果一致。

## 对照 Oracle 与诊断/发布区别

输入核验完成后，对照 [ORACLE.md](../../tests/fixtures/order_boundaries/ORACLE.md) 的 A3-04/A3-05 两节以及 JSON 的冻结 `expected`，未发现业务差异。

| 样例与窗口 | 输入核验的N/U/率 | 冻结发布字段 `metrics` 的N/U/率 | 判断 |
| --- | --- | --- | --- |
| A3-04 基期 | 0 / 0 / null | null / null / null | 空分母，比较阻断 |
| A3-04 当前 | 2 / 1 / 1/2 | null / null / null | 可作诊断，不单独发布本次比较 |
| A3-05 基期 | 2 / 1 / 1/2 | 2 / 1 / 1/2 | 比较前提满足 |
| A3-05 当前 | 1 / 1 / 1 | 1 / 1 / 1 | 比较前提满足 |

诊断值回答“输入有哪些合格订单、问题在哪里”，发布值回答“本次比较是否允许给出业务结论”。A3-04 的诊断 N=0 确认空队列，而发布 N=null 表示不发布，二者不矛盾。当前诊断率1/2不能代替缺失的基期率。

A3-04 基期率是 `0/0`，未定义，不是0%。绝对变化需要已定义的两窗率；相对变化 `(r1−r0)/r0` 还要求基期率非零。因此两项变化均为 null，不能声称上涨50个百分点、上涨100%或无穷大。A3-05 两窗率均已定义且基期率为1/2，才可发布上述变化。

`diagnostic_cohort_metrics` 是 A3-04 静态预期中的诊断记录，不是参考函数已经返回的字段。这里的“发布”只指合成 Fixture 的 `expected.metrics`，不代表生产 API、批准导入或调查系统已验收；`outcome` 也不冒充正式 `TaskView.status`。
