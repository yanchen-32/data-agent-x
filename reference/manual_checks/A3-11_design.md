# A3-11：单地区过滤后按渠道分组设计草案

日期：2026-10-30。状态：**设计及独立台账初稿，未冻结、未实现渠道参考计算、未获用户本人验收**。

## 1. 主题选择与唯一测试目标

选定主题：**在固定域/快照和西北地区过滤下，先形成支付队列，再按稳定channel_id分组；分组与总计的分子、分母和来源必须使用同一Scope。**

依据[G0覆盖矩阵M01](../regression_checks/G0_fixture_coverage.md)：十个主Fixture没有渠道分组固定预期，原有实际订单均为channel_web。渠道目录存在不等于渠道聚合已覆盖。M02合法跨域正例、M03贡献分解、M04退款DQ、M05验收闭环仍是Must，但目前未发现必须先改题处理的阻塞：A3-10已修复参考层缺失产品拒绝；本草案全部关联合法，不依赖新增生产能力。M01是当前最高一组优先事项之一，本例只推进其渠道分组部分，不宣称解决整个三维缺口。

控制其余条件：两窗均非空，全部支付有效且成熟、水位完整，复合键唯一且关联完整；没有未知类别、同名类别、跨域订单、重复退款或生命周期变化。东南干扰行在同一授权域/快照内，排除原因只为地区不匹配。退款时间位于观察期内部，时间边界另由01/02覆盖。两渠道在每窗的N、U、率均不同，用于识别错组、漏过滤及将组率简单平均的错误，而不是增加多个验收主题。

规则依据：

- [DD02 §1/2/4](../../docs/engineering/04_详细设计与实现准备/DataAgentX_DD02_指标数据与SQL工具_v1.2.md)：固定Scope、先地区过滤后分组、订单退款口径、成熟水位、AggregateRow身份与证据边界。
- [指标目录](../../docs/engineering/02_总体设计与方案验证/DataAgentX_指标目录与数据契约_v1.2.md)：每次单维category/region/channel、复合键关联、精确计数和独立逐单Oracle。

| --- | --- |

逻辑顺序是：固定域/快照与地区 → 有效支付及半开窗 → 成熟/水位前提 → 关联同Scope退款并按订单去重 → 按channel_id分组与同Scope总计。产品、地区、渠道目录按各自`(domain_id,snapshot_id,ID)`唯一关联；渠道直接来自订单channel_id，不从产品类别推断。退款无自有渠道字段，通过订单复合键获得渠道归属。

这里只规定结果的业务集合。未来SQL可以采用等价安全实现，但不能把全地区聚合完再从展示结果“过滤”成西北；同一渠道内包含两个地区，聚合后已丢失可恢复的地区归属。

总体绝对变化`5/12 ratio`，相对变化`5/4`；精确率将以Fraction比较，不将1/3或2/3提前截断。六条拟定聚合行是四条channel行加两条总计行。分组身份只取`(channel,channel_web)`或`(channel,channel_app)`；同Scope中以目录label显示。每窗`ΣN组=N总计`、`ΣU组=U总计`，同时比较订单与退款来源集合，避免仅靠守恒掩盖串组。

台账另列人工漏过滤反例：全地区率会变成`2/5→2/3`，绝对变化`4/15`，而非固定西北的`1/3→3/4`和`5/12`。分子/分母仅一侧过滤也会产生看似合法但错误的率，故应核对逐单集合。反例没有独立输入文件、没有运行控制计算，不计新增Fixture或已通过变体。组率变化不是贡献，暂不手算或实现within/structure/entry/exit。

## 4. 为什么现有测试不能替代

| 已有证据 | 能证明什么 | 不能替代本例的原因 |
| --- | --- | --- |
| A3-05固定地区过滤 | 西北总计的分子/分母同时过滤 | 输入只有channel_web，无两渠道数值、身份或来源预期 |
| test_single_region_filters_denominator_and_refunds_before_grouping | 地区过滤后类别分组计数正确 | 分组键是category_id，没有channel结果；不能证明渠道直接归属或渠道目录关联 |
| A3-07同名、改名与产品关联 | 类别身份不依赖展示名 | category与channel是不同维度，本例所有产品恰好属于同一类别 |
| 总体calculate_reference()回归 | 支付队列、退款订单、前提及总体变化 | 没有渠道行或渠道来源台账；仅总计正确可能掩盖错组 |
| A3-08/09六行回归 | 类别生命周期/未知保留及守恒 | 同为六行只是数量巧合，不能代替channel_id分组 |

当前`reference/category_cohort.py`固定输出dimension_id=category；本例不得把channel_id伪装成category_id来套测，也不得把给现有函数加channel参数视为已实现。生产Runtime、SQL、鉴权、DQ状态映射、贡献分解、region维度、跨域正例、offset配对均不在本轮交付内。
