# G0 M01：region分组最小契约与实施方案初稿

日期：2026-11-07（Asia/Shanghai）。状态：**方案初稿，尚未创建region计算器、冻结region预期或执行相关测试。** 本轮只决定业务用途、参考接口与验证边界，不据方案形成关闭M01或G0。

## 1. 业务意义与实现决定

依据[有效DD02 §1/2/4](../../docs/engineering/04_详细设计与实现准备/DataAgentX_DD02_指标数据与SQL工具_v1.2.md)、[SRS §4.1.1](../../docs/engineering/01_需求基线/DataAgentX_SRS_v1.2.md)、[指标目录](../../docs/engineering/02_总体设计与方案验证/DataAgentX_指标目录与数据契约_v1.2.md)及[M01缺口复核](../regression_checks/G0_M01_region_review.md)，区分三种情况：

| Scope | region分组能提供的信息 | 设计决定 |
| --- | --- | --- |
| 已冻结为一个授权地区 | ready时每窗只存在该地区一个组，N/U/率与该窗总计相同；不能再比较地区之间的差异 | 保留单组契约检查，不建设另一个调查流程、排名功能或“地区解释”来重复总计。该Scope中有区分力的分层通常是category或channel |
| 服务端实际授权、冻结的全地区Scope | 授权视图内存在多个实际支付地区时，可核对地区间的率、样本构成及总体变化；属于SRS允许的总体单维分层 | region有独立验证价值，但真实授权视图、SQL及贡献计算仍待各自实现，当前不声称可用于生产 |
| 本地合成全地区控制 | 在同一域/快照内假定测试主体获准访问两地，验证多组、退款归属和守恒 | 作为参考层受控验证，不是获得生产权限的证据 |

**决定：需要一个小型独立region参考入口，用于合法多地区Scope的分组与Oracle对照；单地区结果作为其退化契约验证，不单独复制一套总计算法。** 只有单地区样例不足以证明该入口有区分力，不以补齐三种名称为交付目标。

拟采用`reference/region_cohort.py`中的`calculate_region_reference(data: Mapping[str, Any]) -> dict[str, Any]`，复用总体`calculate_reference()`的队列和比较前提，独立按订单地区归组并核对退款订单；不调用category/channel计算器生成region结果，不提取通用维度引擎，不修改已有计算器或生产Runtime。与“仅把总计包装为一个地区行”相比，该入口必须能验证多地区归属；与重构通用引擎相比，改动限于参考层且保留既有回归边界。

## 2. 授权、过滤与合成控制

生产有效订单集合先受服务端授权域、快照和固定视图限制，之后应用被冻结的地区过滤及支付窗。`region_ids=[]`只表示当前已授权数据范围中的全部地区，不表示获得其他地区权限；`[id]`只能是当前域已登记且主体可访问的单ID。模型不能把单地区Scope改为[]，不能传多个地区ID来扩展R0。

参考函数不验证主体权限、签发Scope或实现名称解析，输入前提是合法固定合成Scope。它不接受绕过参数，也不在函数内改filters。测试中的全地区变体必须先深拷贝，再显式声明“该合成控制假定另获两地授权”，按独立控制绑定输入和预期；原西北Fixture、Scope及证据不覆写。该变体不能作为真实服务端授权、视图隔离或跨域正例的验收证据。

地区名称到ID的解析属于上游：同名需澄清，未知/跨域拒绝或澄清、越权403。参考层只核对固定目录和已解析过滤ID，非法输入抛ValueError，不伪造HTTP状态或生产DQ映射。真实数据若无法证明某条未知地区订单属于授权视图，不得由参考分组逻辑替它授权。

## 3. 身份、目录与来源契约

函数只接收Fixture的`input`，不接收整个Fixture、文件路径、expected或独立人工台账。context保留现有域/快照、指标、双窗、H、as_of、水位和filters；订单/退款沿用原始业务键及source_row_id。

| 对象 | 身份或约束 |
| --- | --- |
| 订单 | `(domain_id,snapshot_id,order_id)`唯一；本参考范围为单品、一次有效支付订单 |
| 退款事件 | `(domain_id,snapshot_id,refund_id)`唯一，关联完整订单键；事件数不等于退款订单数 |
| 地区目录 | `(domain_id,snapshot_id,region_id)`唯一，作为本合成Scope的地区ID登记及展示目录；不能按裸ID或label跨域关联 |
| 产品目录 | `(domain_id,snapshot_id,product_id)`唯一，所有原始订单必须关联成功；产品不决定region归属 |
| 单次输出行 | `(window_index,dimension_id,group_id)`唯一；region行dimension_id="region"、group_id为地区ID，总计dimension_id/group_id为None |
| 跨Scope证据 | 上述行键必须连同域、快照及Scope绑定，不合并不同域中同名、同ID或__unknown__的行 |

目录先检查重复键、域/快照混入及字段格式，再建立索引，避免字典覆盖。关键产品缺失覆盖全部原始订单，包括过滤外、窗口外和比较不足时；按既有A3-10规则拒绝并定位订单ID、来源行及完整产品键。地区目录重复或混域也先拒绝，不能因地区过滤、不成熟或unknown降级而绕过。

原始订单、退款和目录来源只在各自固定Scope内追溯；分组不改变订单粒度，不把一个订单联接成多行。渠道/类别目录仅作为兼容原输入的背景，不在region入口实现它们的分组或扩大其业务检查。

## 4. 未知值与展示名规则

以下为本草案选定的局部参考输入规则，实施前应与人工台账一起明确冻结；它们不是已实现的归一化服务，也不修改现有订单校验或Schema。

| 情况 | 参考层处理 |
| --- | --- |
| 订单缺少region_id，或为null、空串、空白、非字符串 | 格式错误，明确拒绝；不把任意坏格式自动修成未知值。现有validate_order同样要求非空字符串，但参考函数不导入生产校验代码 |
| 订单region_id为预先声明的`__unknown__` | 合法的非关键未知地区数据；保留原始行和来源，在全部地区控制中归入`(region,__unknown__)`，label=None。该哨兵是保留组ID，不是可请求的注册过滤ID |
| 订单有合法非空地区ID，但在已核验的同Scope登记目录中无条目 | 按本草案声明的非关键未知地区关联处理，归入__unknown__并保留原ID及来源供台账披露；不能借其他域的同ID/同名条目补关联。若目录本身重复/混域，仍先拒绝，不适用此降级 |
| 已登记地区ID，仅label缺字段或为null | 保留原地区ID，group_label=None；“已知实体缺展示名”和“目录中无该实体”分开，不能因无label并入未知组 |
| 两个已登记ID使用相同label，或label被改名 | 保持两个身份，N/U/率和台账不变，只修改相应展示字段 |
| 已提供label为空白或非字符串 | 目录字段格式错误，拒绝；不通过清洗或改ID使其看似合法 |

地区目录ID必须是有效非空业务ID，不能把保留的__unknown__登记为普通地区。选择单地区时，过滤ID须已登记，不能把未知过滤参数改成unknown组；`["__unknown__"]`也不属于本契约的过滤输入。缺少整个必需目录字段属于结构错误，不能把目录加载失败解释成全部未知。

已登记单地区Scope内，只有订单原region_id与所选ID相等才进入候选；未知或其他地区订单及其退款不进入该Scope。这是明确过滤，不是静默丢弃本应在队列内的未知组。全部地区的合法合成控制中，非关键未知订单必须保留在分母，合格退款进入同一个unknown组的U，并在手工台账披露原ID/来源和未知规模。

这与关键产品关联不同：产品实体缺失必须拒绝，不能归入地区unknown。目录缺失的非关键处理是本方案的显式分类，不把所有关联错误一概降级，也不照抄最小channel入口的未知ID范围拒绝。

## 5. 支付队列、退款与输出

1. 先核对本地必填结构及region字段格式，再复用`calculate_reference(input)`核验总体输入并取得地区过滤后的双窗candidate_order_ids、成熟/水位和比较状态；不从全量订单另建扩大后的分母。局部目录及关键产品检查必须在比较不足返回之前完成，避免坏字段先触发意外KeyError或错误队列；原始输入保持不变。
2. ready时将本窗候选订单映射为完整订单键集合P，按订单region_id和第4节规则得到互斥集合P_g；地区目录不提供支付计数，不按展示名归组。
3. 从原始退款独立得到R：同域/快照/订单、status=success、refund_at在闭区间[paid_at,paid_at+H]且≤as_of的订单键集合。同单多笔有效退款只在R出现一次；退款发生在哪个日历窗口不改变它所属的支付窗，也不从退款字段推测地区。
4. 各组`N_g=len(P_g)`、`U_g=len(P_g ∩ R)`、`rate_g=Fraction(U_g,N_g)`；只输出实际存在的组。各窗ΣN_g和ΣU_g等于同Scope总计，总计N/U/率再与overall一致；不平均组率，不按渠道占比摊分地区值。
5. 返回保留全部overall字段，并新增aggregate_rows、group_order_ids和group_refunded_order_ids，沿用现有参考接口形状。每窗先总计、后按稳定group_id排序；组台账订单ID排序，overall候选顺序不改。region与总计行计数为int、率为Fraction，group_label仅显示。

原总体比较不足时不发布任何聚合行或分组台账，保留其候选诊断与空指标；ValueError拒绝与insufficient_evidence分开，不生成blocked_by_quality生产对象。N>0/U=0是合法零退款；无订单的地区不补行、不编造零分母退款率。单地区ready时每窗一个地区行和一个总计行，数值相同；全地区多组时行数随实际存在组变化，不以必须六行替代正确性。

来源字段不必扩展为生产QueryEvidence：测试从group_order_ids/分组退款订单回查原始source_row_id、原region_id、目录行及合格退款事件，并与人工台账比较；同单多退款时分别核对事件集合和去重订单集合。unknown归组原因与原ID也写入台账，不能通过改原输入隐藏映射。
