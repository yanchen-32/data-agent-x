# M01-region规则审定：未知数据、展示名与授权边界

日期：2026-11-10（Asia/Shanghai）。规则版本：`M01-region-rules-v1`。状态：**本地参考规则的技术审定已形成，草案所列处理分支均有结论；尚未冻结机器可读预期、实现或运行测试，不代表生产授权批准、用户本人签字或G0验收。**

## 1. 依据与效力范围

依据[DD02 §1/2/4](../../docs/engineering/04_详细设计与实现准备/DataAgentX_DD02_指标数据与SQL工具_v1.2.md)、[SRS §4.1/4.1.1/4.4](../../docs/engineering/01_需求基线/DataAgentX_SRS_v1.2.md)、[指标目录](../../docs/engineering/02_总体设计与方案验证/DataAgentX_指标目录与数据契约_v1.2.md)及有效[对象Schema](../../docs/engineering/04_详细设计与实现准备/DataAgentX_对象Schema_v1.2.1.json)中的BusinessFilters。它们要求先授权和固定Scope，再过滤/聚合；非关键未知维度留组披露；未知过滤参数不能扩大Scope；显示名不决定分组身份。

DD02给出原则，未逐项规定Python订单字段的null/空白表示或目录缺项的所有实现分支。本记录在该原则内确定最小参考输入规范与授权前提，不能将这些局部选择冒称DD02逐字原文或新增生产DQ状态。

本次审阅的[region方案](G0_M01_region_plan.md)、[人工台账](G0_M01_region_expected_draft.md)和[测试矩阵](G0_M01_region_test_matrix.md)已随[2fe6d51](https://github.com/yanchen-32/data-agent-x/commit/2fe6d51d9c1f0797b09930b875a47e4f70f2ada6)公开。三份原稿及其哈希保持不变；其中“未知规则待审定”保留历史含义。后续实施以既有冻结契约为上位依据，以本记录限定局部规则，不通过改写旧草案或expected消除差异。

## 2. 总原则：授权不明不能降级为数据未知

**先证明数据属于可访问的固定输入，再决定其非关键地区信息是否未知。** `domain_id`与context一致、字段名称或ID前缀相似、目录中找不到ID、或值恰为__unknown__，都不能单独证明一行已获授权。

真实路径的授权范围由服务端固定视图/数据边界及冻结Scope保证，不能只在最终报告过滤。若某行来源、访问域或允许的数据范围无法确认，应在进入计算前拒绝该输入/查询，不发布不确定授权数据的指标；也不先删除可疑行后把剩余样本当作完整结果。主体明确无权访问时，生产授权层按既有规则403；其他来源/DQ不确定问题不能一概伪造为403。

本最小参考函数不实现权限判断，也不接收一个可由调用者随意设为true的“已授权”开关。它只接收已完成结构/Scope预审的受控合成input；调用侧以固定输入/变更清单、来源及哈希约束这个前提。测试的授权假设是案例前提，**不是已经实现或通过的真实授权检查**。

## 3. 审定规则表

| 编号 | 场景 | 明确结论 | 依据及限制 |
| --- | --- | --- | --- |
| RR01 | 未登记的源订单地区ID，非空字符串，在同Scope登记目录无条目 | **有条件采用归unknown**：须已属于获准固定输入，目录整体已按正确快照核验，且单个地区关联缺失按该参考版本声明为非关键问题；候选内归`(region,__unknown__)`，group_label=None，保留原ID/来源/归类原因，不删除订单 | DD02非关键未知留组原则；不能仅凭“未登记”断言问题非关键或已授权。授权/快照/目录完整性不明时拒绝计算，不适用此降级 |
| RR02 | 源订单region_id已经为`__unknown__` | **采用显式未知哨兵**：与RR01受相同授权前提约束；被合法Scope纳入时保留N及合格退款U，不额外登记为普通地区实体 | SRS明确未知地区组ID；该字符串不带访问权，也不覆盖关键问题 |
| RR03 | 当前Scope已登记地区实体，label缺字段或为null | **保留原group_id，group_label=None**，N/U/率和来源不变，不并入unknown | DD02分组身份与展示名分离；缺少整个实体条目属于RR01的另一分支，不能混称为“仅缺展示名” |
| RR04 | 两个已登记ID同名，或仅改名 | **保持两个身份/数值/台账**；仅相应group_label变化；名称解析产生歧义时由上游澄清，不能把同名实体合并 | 同域按稳定ID，目录关联使用(domain_id,snapshot_id,region_id)；跨Scope行不能只按局部ID拼接 |
| RR05 | 本地规范化参考订单缺region_id、为null/空串/纯空白/非字符串 | **结构拒绝，ValueError**；不转字符串、不自动修成__unknown__，不原地清洗输入 | 是本地参考表达选择，不新增全局订单Schema。raw缺失若需规范为未知，应另有明确的导入/快照规则；本轮不实现该服务 |
| RR06 | 未登记、跨Scope、保留哨兵或结构非法的过滤参数 | **拒绝或在名称解析层澄清，不进入分组计算**；最小参考输入验证用ValueError，不能改成[]、归unknown或当正常空窗 | DD02/SRS和BusinessFilters；未知过滤参数与未知订单数据是不同对象 |
| RR07 | 地区/产品目录重复键、域/快照混入，关键产品关联缺失 | **明确拒绝，不能归unknown**；关键产品缺失须定位订单、来源及完整键，过滤外或比较不足也不豁免 | 沿用现有关键规则，不改变A3-10及C04语义；ValueError不是生产blocked_by_quality实现 |
| RR08 | 目录字段整体缺失、加载不完整或版本不可信 | **拒绝输入/计算**；不能把目录失败解释为“所有地区均未知” | 单个非关键实体缺项与整个登记依据失效不同；不能利用空目录遮蔽跨域或未登记过滤ID |
| RR09 | 已提供label为空白或非字符串 | **目录字段格式拒绝**；不修改ID来掩盖错误 | 缺字段/null才是RR03的合法缺展示名表示；不隐式修复原数据 |
| RR10 | `__unknown__`被登记为普通目录ID，或被当作可请求过滤地区 | **拒绝该参考输入/过滤**；保留它作为组ID | 保留哨兵不能与真实地区身份冲突；不是SQL标识符或“查看全部未知数据”的访问入口 |

RR01的条件是明确边界，不是待选政策：条件满足时留组，条件不满足时不得计算该不确定授权输入。生产上是否已满足授权不能由本参考函数猜测；当前只通过受控合成前提使用它，不宣称存在生产授权实现。

## 4. Scope与执行先后顺序

1. **授权与快照前提。** 确保调用侧提供的是当前主体可访问的固定域/快照数据，记录来源及版本。授权无法确认时停止，不能靠unknown映射恢复合法性。
2. **结构和关键检查。** 必填结构/字段、目录唯一性/Scope、订单退款键与时间、关键产品关联保持原拒绝边界；其中全部原始订单关键关联覆盖过滤外记录。关键错误不能被后续成熟不足掩盖。
3. **验证过滤并先选队列。** []仅表示当前已经获准范围内全部地区；单ID须当前域已登记且获准，过滤按订单原region_id精确匹配，再结合半开支付窗及有效支付形成候选。不先把未知改成某个已登记ID再筛选，不在函数内部改filters。
4. **仅在候选内归组。** 全地区受控Scope下RR01/RR02的非关键未知留在分母，合格退款按支付订单归同组、同单只计一次。单地区Scope下未匹配所选ID的未知/其他地区订单不进入队列，也不生成unknown行；这是授权前提成立后的查询过滤，不是对授权不明数据的处置办法。
5. **保持状态区别。** 合法数据但成熟/水位/空窗不足沿用insufficient_evidence、不发布两窗指标；非法参考输入用ValueError；真实授权层拒绝在上游。本记录不增加生产状态码、恢复流程或权限逻辑。

已登记地区即使无label，仍可按其ID作合法单地区过滤，前提是主体有权且过滤格式有效；不能因为缺展示名扩大为[]。反之，知道一个地区名称或局部ID并不能获得该地区访问权。

## 5. 非法过滤ID的完整处理

有效BusinessFilters要求显式region_ids数组、至多一个且唯一的字符串ID；ID模式为`^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`。其中：

- `[]`：只有授权前提成立才代表该范围全部地区，不能把用户明确单地区意图忽略为全部；缺字段也不能由参考函数偷偷默认[]。
- `["region_northwest"]`：还需同Scope登记与上游授权，语法合法不等于有权访问。
- `["region_unregistered_filter_rg05"]`：即使语法合法，未登记也拒绝，不能变成unknown组或空窗结果。
- `["__unknown__"]`：保留哨兵不是注册过滤ID，且不满足该ID模式；不能借此筛出授权未明的未知来源。
- 两个ID、重复ID、直接名称、非字符串、null、错误容器或多余字段：按既有Schema/SRS拒绝；名称解析只在上游处理，同名先澄清，不能用同名替代ID。
- 外域ID/目录或已知但无权访问的ID：不能借裸ID/同名匹配；真实越权由授权层拒绝，参考层不模拟HTTP状态。

该正则只用于引用已存在的过滤契约，不把它擅自推广成新的全局订单行Schema。所有拒绝均不得返回看似正常的分组数值。
