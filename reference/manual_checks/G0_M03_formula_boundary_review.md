## 2. Scope、实际存在组和集合

记t=0为基期、t=1为当前。两窗沿用同一固定域/快照、指标、H、as_of、地区过滤及水位契约；先应用授权Scope与地区过滤，再形成支付队列及单个维度分组。每单按已登记H满足成熟条件，两类水位及必需DQ均须通过，且两个窗口总体分母N_t均大于0；本阶段既有合成默认H=604800秒（7天），不另改指标期限。

一次只分解category、region或channel中的一个维度。组身份为当前Scope内的(dimension_id,group_id)，不是group_label；产品/订单/退款关联继续使用包含domain_id、snapshot_id的完整键。不能混合不同Scope、按展示名合并、把其他域或其他维度的贡献加到本分解中。

G_t为窗口t中实际有支付订单的组集合，即每个组N_{i,t}>0。仅存在目录记录但没有支付不构成该窗业务组。

| 生命周期 | 集合定义 | 参与的贡献 |
| --- | --- | --- |
| shared | G_0 ∩ G_1 | within和structure各一项 |
| exit | G_0 − G_1 | 仅使用基期的exit |
| entry | G_1 − G_0 | 仅使用当前的entry |

三类互斥，并集恰为G_0 ∪ G_1。合法非关键未知组__unknown__同样参与实际组集合、权重及生命周期，不能丢弃。已知ID缺展示名或改名仍保留原ID；关键产品关联缺失等DQ异常仍应拒绝，不得用unknown降级后继续分解。

## 3. 计数、权重和退款率

N_{i,t}为实际组的有效支付订单数，U_{i,t}为这些支付订单中至少一次合格成功退款的订单数；同单多事件只使U计一次。退款按所属支付订单及支付窗口归组，不能按退款事件的日历窗口另建分母。

对i∈G_t，定义：

```text
N_t     = Σ(i∈G_t) N_{i,t}
U_t     = Σ(i∈G_t) U_{i,t}
w_{i,t} = N_{i,t} / N_t
r_{i,t} = U_{i,t} / N_{i,t}
R_t     = U_t / N_t = Σ(i∈G_t) w_{i,t} × r_{i,t}
Δ       = R_1 − R_0
```

权重分母是**该窗过滤后总体支付单数**，不是两窗合计、退款单数或组数。分组须互斥穷尽，0≤U_{i,t}≤N_{i,t}，每窗ΣN组=N_t、ΣU组=U_t、Σw=1。总体率用汇总U/N，不能简单平均组率。

## 4. DD02冻结公式

下式中的w_0/r_0与w_1/r_1均指同一个shared组的两个窗口值；R_t专指总体率，避免与组率混淆。

```text
i ∈ shared:
    within_i    = ((w_{i,1} + w_{i,0}) / 2) × (r_{i,1} − r_{i,0})
    structure_i = ((r_{i,1} + r_{i,0}) / 2) × (w_{i,1} − w_{i,0})

i ∈ entry:
    entry_i = w_{i,1} × r_{i,1}

i ∈ exit:
    exit_i  = −w_{i,0} × r_{i,0}

C = Σ(shared) within_i + Σ(shared) structure_i
  + Σ(entry) entry_i + Σ(exit) exit_i
```

within使用两窗平均权重，structure使用两窗平均组率；不能自行改为只用基期/当前权重，不能另选一种分解再用“残差接近0”证明符合契约。entry为非负项，exit为非正项；shared的两项都可能正、负或零，不能用绝对值代替符号。

entry/exit仅使用实际存在窗口的w与r，不访问缺席窗的退款率，不伪造N=0的聚合行，也不补一个r=0供对称公式使用。within/structure不适用于缺少一窗的组；这不是说该组本身的贡献不存在，而是其贡献已由单独entry/exit项完整表示。

## 5. 精确重构证明与残差

共享组的恒等式可直接展开：

```text
within_i + structure_i
 = 1/2 × (w1*r1 − w1*r0 + w0*r1 − w0*r0)
 + 1/2 × (w1*r1 + w1*r0 − w0*r1 − w0*r0)
 = w1*r1 − w0*r0
```

分别对两个窗口的实际组求和，不定义缺席组率：

```text
C = Σ(shared)(w1*r1 − w0*r0)
  + Σ(entry)(w1*r1) − Σ(exit)(w0*r0)
  = Σ(i∈G1)(w1*r1) − Σ(i∈G0)(w0*r0)
  = R1 − R0 = Δ
```

因此完整输入下各贡献项精确重构总体变化。本记录在检查中记residual=Δ−C；残差符号只是说明记法，契约要求仍是DD02的绝对残差≤1e-6。整数/Fraction且未舍入的计算满足residual=Fraction(0)，这是上述恒等式的结果；不另改DD02正式容差，不把小于阈值当作组丢失或更换公式的许可。

阈值写为Fraction(1, 1_000_000)，不是浮点1e-6。总体Δ=0时仍按绝对残差比较，不能用residual/Δ；各项非零而净和为0属于合法抵消，不能强制每项为0。

## 6. 必须保留的边界

| 边界 | 冻结处理及检查依据 |
| --- | --- |
| 一窗总体N=0 | 总体率及组权重不可用于可比贡献，不能借entry/exit把整体不足变成正常变化；沿既有上游不足/拒绝规则，不在本记录新造生产状态或异常接口 |
| DQ失败、成熟不足或水位不足 | 不发布看似完整的可比贡献；水位及成熟等号仍沿既有DD02允许，不重新定义观察期 |
| 组N>0且U=0 | 是真实存在组，r=Fraction(0)；仍参与生命周期和权重，不当作缺席。零退款entry/exit可具有精确零贡献 |
| 缺席组 | 没有该窗聚合行/组率，不能生成0/0或伪造零率；只用存在窗的entry/exit，目录存在不改变结论 |
| 基期总体R_0=0但N_0>0 | Δ和四类贡献仍可计算；相对变化因除零为null，贡献公式不依赖相对变化，不得跟随相对变化一起无依据阻断 |
| shared组基期率为0 | 不是缺席，对称within/structure合法；组自身相对变化不可定义不影响本分解 |
| 组率不变 / 组权重不变 | shared组率不变则within=0；权重不变则structure=0；真实符号与零值均保留 |
| shared、entry或exit集合为空 | 对应贡献和为Fraction(0)，不是异常；无需补组凑齐三类 |
| 组丢失、重复、来源/Scope不一致或ΣN/ΣU不守恒 | 不具备完整分解前提，不能用舍入、残差摊平、重命名或unknown吞掉差异；DD02禁止截断后声称完整贡献 |
| 合法未知、展示名缺失或改名 | 保留真实组身份并参与同一套公式；未知也可shared/entry/exit，不因label变化制造生命周期变化 |
| 同时查看多个维度 | 每个维度各自重构相同总体Δ，彼此不是可加的贡献集合，不能跨维求和 |

上述是规则检查，不表示这些边界已新增测试或实现；冻结规则确定与执行覆盖状态分别记录。

## 7. Fraction、单位和表达边界

计数保持int；从整数构造Fraction(U, N)、Fraction(N_i, N_total)，二分之一用Fraction(1, 2)，空集合求和起点用Fraction(0)。禁止先用/形成float再传Fraction，也不在分项、权重或中间组率处舍入。

贡献内部单位为**ratio（比例差）**，与Δ同单位，不是相对变化百分比、退款订单数或每个组自身率变化。显示百分点=贡献ratio×100；例如ratio=1/100表示1个百分点，不等于在某个基期上相对增加1%。贡献和对应总体绝对率差，不拿总体相对变化作为重构目标。

DD02既有序列化边界保持：Fraction转Decimal精度50、ROUND_HALF_EVEN，规范字符串去尾零/负零；显示百分数两位ROUND_HALF_UP。百分点数值同样先由ratio乘100得到，不用已舍入显示值反向计算贡献、做残差或合并维度。本次只记录这些规则，不实现生产序列化。

within、structure、entry、exit是对已观察总体率变化的代数/会计分解。可以描述哪些数值项增加或抵消总体变化，**不能称为因果效应、干预收益、反事实解释或证明某类别导致变化**；相同标签和关联也不提供因果识别。
