## 后续验收方式与本轮证据

- 先用三个独立变体复核上述故障个数及来源键，再对同一个公开参考入口 `calculate_reference()` 写参数化拒绝断言。预期分别命中重复退款事件、孤立退款、退款早于支付的 `ValueError`，调用无法取得正常比较对象。三个分支由各分组入口复用。[参考入口](../cohort.py)
- 对各变体保留原始输入字节、规范化指纹和变更前后对应行。A3-07 原文件 SHA-256 为 `e03a1c005e6f99f5e497e452bb3de5e75aa2096f83106f730a45ebcbbec737ac`，规范化 input SHA-256 为 `cb458cfb0bc5555c8c680bab64885c0f2fd2e212951a12143260eb9ea3e339ca`。规范化采用 UTF-8、键排序、紧凑分隔并保留数组顺序。
- `blocked_by_quality` 是本清单中的业务发布预期。现有参考层验收以异常阻断为准。正式 DQ Adapter、质量状态映射、诊断证据与生产授权由 M06 验收。
- 必需 `refund_at` 缺失仍是已确认缺口，排在本批三个单一故障之后。它应独立按 DD02 验证，不能用本批支付前退款或订单 `paid_at` 校验代替。金额合法性等待冻结口径定义。

本轮标准库静态核验退出码为 0。只在内存中构造三份变体，核对完整键、唯一来源行、支付队列、成熟与水位以及每项唯一故障。原始 Fixture 字节一致，未执行参考拒绝测试。M04 当前状态为已选定增量验收范围。
